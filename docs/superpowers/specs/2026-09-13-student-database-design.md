# TheAll Messenger — 학생 관리 데이터베이스 설계

**날짜**: 2026-09-13
**상태**: 설계 승인됨, 구현 계획(writing-plans) 대기

## 배경 및 목표

기존 방식: 선생님이 학생 출결/일정 정보를 엑셀 또는 PDF로 수동 업데이트하면,
조교가 그 파일을 다운로드해서 기존 파일을 덮어쓰는 구조로 운영해왔다. 이 구조는
버전 충돌, 실시간성 부재, 수작업 반복이라는 문제가 있다.

이 프로젝트는 노션(Notion)처럼 선생님과 조교가 **같은 화면에서 실시간으로
같이 기록하고 확인**할 수 있는 학생 관리 데이터베이스를 만드는 것이 목표다.

> 참고: 초기에는 "선생님-조교 1:1 채팅" 형태(메신저)로 기획을 시작했으나,
> 논의 결과 자유형식 채팅 대신 구조화된 기록(코멘트, 인수인계 메모, 학생별
> 예외사항)이 그 커뮤니케이션 역할을 대체하는 것으로 방향을 바꿨다. 별도의
> 자유형식 채팅 기능은 이 설계에 포함하지 않는다.
>
> 이전에 만든 클릭 가능한 UI 목업(채팅 인터페이스,
> https://claude.ai/code/artifact/decaab63-37e5-4e5d-b928-ac62a6499cd8)은
> 이 방향 전환 이전의 산출물이라 현재 설계와 맞지 않는다. 실제 화면(학생
> 테이블, 캘린더 뷰 등)은 아래 서브프로젝트별 구현 계획 단계에서 새로
> 설계한다.

## 아키텍처 (기존 스파이크 조사에서 확정)

- 학원에 이미 구축된 **Synology NAS**의 Container Manager(Docker)에 Node.js
  백엔드(WebSocket + 저장소)를 상시 컨테이너로 배포한다. NAS는 24시간
  켜져 있어 별도 서버를 구축/운영할 필요가 없다.
- 선생님 PC와 조교 PC의 **Electron 앱은 순수 클라이언트**로, 학원 내부망(LAN)을
  통해 NAS 백엔드에 접속한다.
- 데이터 저장소(예: SQLite)는 **NAS 로컬 파일시스템**에 둔다. SMB/CIFS 같은
  네트워크 공유 위에 DB 파일을 직접 두면 락킹 호환성 문제로 손상 위험이
  있으므로, 클라이언트가 파일을 직접 공유 접근하는 방식은 쓰지 않는다 —
  모든 접근은 NAS 위에서 도는 백엔드 프로세스를 통한 네트워크 요청으로만
  이루어진다.
- NAS 컨테이너는 학원 LAN에서만 접근 가능하도록 제한하고, 간단한 토큰
  인증을 둔다.
- Electron 보안 기본값: `contextIsolation: true`, `sandbox: true`,
  `nodeIntegration: false`, preload + `contextBridge`로 메인↔렌더러 통신.

## 범위 분해 (서브프로젝트 및 구현 순서)

전체 기능을 한 번에 구현하지 않고 아래 순서로 나눠서 각각 설계→계획→구현
사이클을 거친다. 뒤 단계는 앞 단계의 데이터를 참조한다.

1. **학생·수업·클리닉 마스터 데이터** — 매주 반복되는 기본 일정 (이 문서에서
   데이터 모델까지 확정)
2. **출결 & 예외사항** — 날짜별 실제 기록: 출결 체크, 일정 예외(결석/시간변경/
   보충), 학생 코멘트, 미출석 알림
3. **인수인계 메모** — 조교 간 하루 단위 전달 사항
4. **조회/내보내기 뷰** — 캘린더(카테고리별) + 엑셀/PDF 내보내기

각 서브프로젝트는 이 데이터 모델을 기반으로 별도의 구현 계획을 세운다
(화면 와이어프레임, API 엔드포인트, 검증 규칙 등은 해당 계획 단계에서
확정).

| 필드 | 필수 | 설명 |
|---|---|---|
| 활성화 여부 | 필수 | 기본값 false(꺼짐) |

기능은 필요해지면 추가).

## 미출석 알림 동작 방식

1. 백엔드가 Class/ClinicAssignment(반복 일정)와 ScheduleException(당일
   결석·시간변경 반영)을 조합해 "지금 이 시간에 와야 할 학생 명단"을
   계산한다.
2. 설정된 지연 시간이 지나도 해당 학생의 AttendanceLog에 등원시각 기록이
   없으면, 이미 연결되어 있는 WebSocket을 통해 조교 앱으로 알림을 push한다.
3. Electron 클라이언트는 이를 데스크톱 알림으로 표시한다.
4. 알림 기능은 기본적으로 꺼져 있으며, 설정 화면에서 켜고 지연 분을
   입력할 수 있다.

## 캘린더 / 내보내기 뷰 (개요)

- 캘린더는 정규수업 / 클리닉 / 보충 / 결석 / 일정변경을 카테고리(색상)로
  구분해서 표시한다.
- 같은 데이터를 엑셀과 PDF로도 내보낼 수 있어야 한다.
- 화면 레이아웃, 필터링, 내보내기 포맷의 구체적인 사양은 서브프로젝트 4
  구현 계획 단계에서 정한다.

## 이 설계에서 다루지 않는 것 (다음 단계에서 결정)

- 각 서브프로젝트의 실제 화면 와이어프레임 및 UI
- NAS 백엔드의 API 엔드포인트 명세, 인증 토큰 발급/관리 방식
- 엑셀/PDF 내보내기의 정확한 포맷
- 형제자매 연결, 일정 예외 등에 대한 구체적인 유효성 검증 규칙

이 항목들은 각 서브프로젝트를 구현 계획(writing-plans)으로 넘길 때
확정한다.
